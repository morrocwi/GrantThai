# ใช้ GrantThai คู่กับผู้ช่วย AI

ฉบับภาษาอังกฤษ: [`docs/use-with-ai.md`](../use-with-ai.md)

GrantThai ใช้ได้เต็มที่โดยไม่ต้องมี AI หน้านี้เขียนไว้สำหรับนักวิจัยที่อยากให้ AI
ช่วยสัมภาษณ์ แล้วเตรียมไฟล์ตั้งต้น `work.yaml` (ไฟล์ `project.yaml` แบบเดิมยังใช้ได้เหมือนเดิม)
กับไฟล์ภาพรวมเพียงไฟล์เดียวต่อ **เส้นทางผลลัพธ์ที่นักวิจัยเลือกเอง** ได้แก่
`build/NRIIS_SUBMISSION.md` (ข้อเสนอโครงการสำหรับกรอก NRIIS ด้วยมือ)
`build/ACADEMIC_ARTICLE.md` (ภาพรวมต้นฉบับบทความวิชาการ) หรือ
`build/RESEARCH_CONCEPT_NOTE.md` (concept note) ตั้งแต่ v0.3 การลงใน NRIIS
เป็นแค่ทางเลือกหนึ่งของ router ไม่ใช่แกนหลักอีกต่อไป

ไม่ว่าจะใช้ AI ของค่ายไหน หลักการเหมือนกันทุกตัว

- **ข้อมูลของนักวิจัยคือแหล่งข้อมูลจริง** สิ่งที่นักวิจัยพูดจะถูกบันทึกว่าเป็นของนักวิจัย
  ส่วนข้อความที่ AI เขียนเองจะถูกบันทึกเป็น "ร่างของ AI" (`ai_draft`, `INFERENCE`)
  ที่นักวิจัยต้องอ่านและยืนยันเอง ร่างของ AI ไม่มีทางถูกบันทึกเป็นแหล่งอ้างอิงได้ ระบบจะปฏิเสธทันที
- **AI ไม่ได้เป็นผู้รับรองความรู้** การตรวจของ GrantThai ดูแค่ว่าข้อมูลครบและเชื่อมโยงกันถูกโครงสร้างหรือไม่
  ไม่ได้ตัดสินว่างานวิจัยดีหรือไม่ดี
- **ไม่แต่งข้อเท็จจริงเรื่องทุนไทยหรือวารสารขึ้นเอง** ระเบียบทุน กำหนดส่ง อัตราค่าใช้จ่าย คุณสมบัติผู้ขอทุน
  ชื่อช่องใน NRIIS และลำดับแท็บ ต้องมาจากประกาศทุนฉบับปัจจุบันที่นักวิจัยมีอยู่ในมือ
  ขอบเขต การอยู่ในฐานข้อมูล จำนวนคำ ค่าธรรมเนียม และระยะเวลาพิจารณาของวารสาร ต้องมาจาก
  คำแนะนำผู้เขียนฉบับปัจจุบันของวารสารที่นักวิจัยให้มา ถ้าไม่มีก็ต้องเขียนไว้ว่า `NEEDS_VERIFICATION`
- **นักวิจัยเป็นคนเลือกเส้นทาง AI ไม่เลือกแทน** AI จะแสดงรายการเส้นทางแล้วถาม
  ถ้าไม่มีอะไรที่นักวิจัยประกาศไว้ชี้ขาดได้ GrantThai จะหยุดแล้วแสดงตัวเลือกให้ ไม่เดา
- **ทุกค่าอยู่ที่สถานะ `DRAFT` สูงสุด และไม่มีอะไรถูกส่งออกไปไหน** นักวิจัยเป็นคนนำข้อมูลไปกรอกใน NRIIS
  หรือส่งต้นฉบับให้วารสารเอง

GrantThai ไม่ใช่ระบบทางการ ดูรายละเอียดใน [`NOTICE`](../../NOTICE)

## AI ใช้อะไรบ้าง

| ส่วน | อยู่ที่ | คืออะไร |
|---|---|---|
| สกิล | `skills/grantthai/` | `SKILL.md` คือคำสั่งที่ AI ทุกค่ายทำตามได้ (ขั้นที่ 0 คือ "ถามว่าจะเอาเส้นทางไหน") ในโฟลเดอร์ `reference/` มีรายการเส้นทาง ชุดคำถามสัมภาษณ์ทั้งแบบข้อเสนอโครงการและแบบบทความ หลักการบันทึกที่มาของข้อมูล คำอธิบายกฎตรวจเป็นภาษาไทย รูปแบบไฟล์คำตอบ และข้อความสำหรับวางในแชต ส่วน `scripts/grantthai_skill.py` เป็นตัวช่วยสั่งงาน |
| ตัวระบบ | `src/grantthai/` | คำสั่ง `grantthai` และ Python API (`grantthai.api_py`) ได้แก่ `init` `set` `validate` `explain` `build --route` `fields --route` `route list|check|build` `migrate` |
| ข้อความสำหรับวางในแชต | `skills/grantthai/reference/PROMPT_PACKET.md` | ข้อความชุดเดียวสำหรับวางในแชตของ AI ที่รันโปรแกรมไม่ได้ (แบบข้อเสนอโครงการ และแบบบทความท้ายไฟล์) |

MCP server และ HTTP API ก็เป็นตัวห่อบาง ๆ ของ Python API ชุดเดียวกันนี้
ใช้หลักการเดียวกัน และได้ไฟล์ผลลัพธ์ไฟล์เดียวเหมือนกัน

## ขั้นที่ 1: ติดตั้งตัวระบบ (สำหรับ AI ที่รันคำสั่งได้)

ต้องมี Python 3.10 ขึ้นไป แล้วรันในโฟลเดอร์ GrantThai ที่ดาวน์โหลดมา

```bash
pip install -e .
grantthai --version
```

ควรติดตั้งแบบ `-e` เพราะใน v0.1 ตัวระบบยังอ่านข้อมูลจากโฟลเดอร์ `spec/` `registry/`
`templates/` และโฟลเดอร์ข้อมูลอื่นในที่เดิม ถ้าติดตั้งวิธีอื่น ให้ตั้งค่า `GRANTTHAI_HOME`
ชี้ไปที่โฟลเดอร์ GrantThai ระหว่างทำงาน GrantThai ไม่ดาวน์โหลดอะไรจากอินเทอร์เน็ตเลย

## ขั้นที่ 2: ส่งสกิลให้ AI ที่ใช้

### Claude Code

คัดลอกโฟลเดอร์สกิลไปไว้ในโฟลเดอร์สกิลส่วนตัว หรือไว้ในโปรเจกต์ที่กำลังทำ

```bash
cp -r skills/grantthai ~/.claude/skills/grantthai          # ใช้ได้ทุกโปรเจกต์ของตัวเอง
cp -r skills/grantthai .claude/skills/grantthai            # ใช้เฉพาะโปรเจกต์นี้
```

จากนั้นเปิดเซสชันในโฟลเดอร์งาน แล้วพิมพ์ เช่น
"ช่วยเตรียมข้อเสนอโครงการสำหรับ NRIIS ด้วย GrantThai" หรือ
"ช่วยเตรียมภาพรวมต้นฉบับบทความวิชาการด้วย GrantThai" สกิลจะถูกเรียกใช้เองจากคำอธิบายของมัน
ถ้าแจกจ่ายสกิลในรูปปลั๊กอิน ก็วางโฟลเดอร์นี้ไว้ในโฟลเดอร์ `skills/` ของปลั๊กอินได้

### Codex CLI และเอเจนต์อื่นที่อ่านไฟล์ `AGENTS.md`

วางโฟลเดอร์สกิลไว้ข้างข้อเสนอโครงการ แล้วสร้างไฟล์ `AGENTS.md` ในโฟลเดอร์เดียวกัน

```markdown
# AGENTS.md
เมื่อขอให้ช่วยเรื่องข้อเสนอโครงการวิจัย NRIIS หรือ GrantThai ให้อ่าน
skills/grantthai/SKILL.md และทำตามทุกข้อ รวมถึงไฟล์ทุกไฟล์ที่อ้างถึงใน
skills/grantthai/reference/
```

ถ้าเวอร์ชันที่ใช้รองรับโฟลเดอร์สกิล จะคัดลอก `skills/grantthai` ไปไว้ที่นั่นแทนก็ได้

### Gemini CLI

ทำแบบเดียวกับข้างบน แต่ตั้งชื่อไฟล์เป็น `GEMINI.md` และใส่ข้อความเดียวกัน

### ChatGPT, Gemini หรือ Claude บนเว็บหรือแอปแชต

- **ถ้ามีฟีเจอร์โปรเจกต์หรือผู้ช่วยที่ตั้งคำสั่งและแนบไฟล์ได้** ให้แนบ `SKILL.md` กับไฟล์ใน `reference/`
  แล้วตั้งคำสั่งว่า "ทำตาม SKILL.md" ผู้ช่วยจะรันการตรวจของ GrantThai ได้ก็ต่อเมื่อรัน Python
  ที่มี GrantThai อยู่ได้จริง ถ้าไม่ได้ ให้ใช้วิธีวางข้อความในแชตด้านล่าง
- **ถ้าเป็นแชตธรรมดา** ให้คัดลอกข้อความระหว่างเส้น `=====` ใน `reference/PROMPT_PACKET.md`
  ไปวางเป็นข้อความแรก

### โมเดลที่รันในเครื่องและ AI อื่น ๆ

- ถ้า AI รันคำสั่งในเครื่องได้ ให้ใช้ `SKILL.md` เป็นคำสั่งหลัก (system prompt)
  แล้วให้มันรัน `grantthai` และ `skills/grantthai/scripts/grantthai_skill.py`
- ถ้ารันไม่ได้ ให้ใช้ `reference/PROMPT_PACKET.md` แล้วบันทึก YAML ที่ได้เป็น
  `project.yaml` จากนั้นรัน `grantthai build project.yaml` เอง

## ขั้นที่ 3: ทำงานร่วมกันหน้าตาเป็นอย่างไร

0. AI แสดงรายการเส้นทางผลลัพธ์ (`grantthai route list`) แล้วถามว่าตอนนี้จะเอาแบบไหน:
   ข้อเสนอโครงการสำหรับ NRIIS บทความวิชาการ หรือ concept note แล้วบันทึกคำตอบของนักวิจัย
   (`--route` หรือ `project.route` ในไฟล์คำตอบ) AI ไม่เลือกแทน จะขอเส้นทางที่สองจากไฟล์เดิมทีหลังก็ได้
1. AI ตรวจว่าตัวระบบพร้อม (`python skills/grantthai/scripts/grantthai_skill.py check`)
   แล้วสร้าง `work.yaml` (`grantthai init work.yaml --work-type ...`)
2. ก่อนขอข้อมูลใด ๆ AI จะแสดงคำเตือนเรื่องข้อมูล (`grantthai_skill.py warning`) คือ อย่าให้ AI สาธารณะ
   ได้ข้อมูลส่วนบุคคลที่ระบุตัวตนได้ ข้อมูลของผู้เข้าร่วมวิจัย ข้อมูลลับ ข้อมูลที่ยังไม่ตีพิมพ์ สิ่งที่จะจดสิทธิบัตร
   หรือข้อมูลที่ใช้ได้สองทาง ชื่อสมาชิกทีมให้นักวิจัยกรอกเอง และ AI จะบันทึกชื่อกับเวอร์ชันของตัวเองไว้ในแบบแจ้งการใช้ AI
   (`docs/policy/ai-use-ceiling.th.md`)
3. AI ขอดูประกาศทุน (เส้นทางข้อเสนอโครงการ) หรือคำแนะนำผู้เขียนของวารสาร (เส้นทางบทความ) ก่อน
   แล้วสัมภาษณ์ทีละหัวข้อตาม `reference/interview.md` หรือ `reference/interview-article.md`
   ทุกข้อเท็จจริงจะถามว่า "รู้เรื่องนี้จากไหน" ในเส้นทางบทความ ผลการศึกษาเป็นของนักวิจัย
   AI แค่จัดเรียง ไม่เขียนผลให้
4. AI บันทึกคำตอบด้วย `grantthai_skill.py apply answers.yaml` (หรือ `grantthai set ...`)
   ข้อความที่ AI ร่างเองจะถูกติดป้ายว่าเป็นร่างของ AI
5. AI รัน `grantthai_skill.py report --route ID` ซึ่งจะตรวจข้อมูลตามเส้นทางนั้น อธิบายผลตรวจระดับ BLOCK และ REVIEW
   ทุกข้อเป็นภาษาไทย แสดงรายชื่อช่องที่ AI ร่างไว้และรอนักวิจัยยืนยัน แล้วสร้างไฟล์ผลลัพธ์
6. AI ส่งไฟล์ผลลัพธ์ไฟล์เดียวของเส้นทางนั้น (`build/NRIIS_SUBMISSION.md`, `build/ACADEMIC_ARTICLE.md`
   หรือ `build/RESEARCH_CONCEPT_NOTE.md`) และ `work.yaml` ของนักวิจัยคืนให้ สำหรับบทความ
   `manuscript_ready` แปลว่าไม่มี BLOCK ค้างเท่านั้น ไม่ได้แปลว่าส่งได้หรือตอบรับแล้ว

ก่อนนำอะไรไปใช้ ให้อ่านส่วนสรุปความพร้อมในไฟล์ผลลัพธ์ และส่วน
"AI-drafted values (the researcher must confirm)" ซึ่งเป็นรายการที่ AI ร่างไว้ให้ก่อน
แล้วอ่านหัวข้อ 4.7 แบบแจ้งการใช้ AI (ภาคผนวกของ GrantThai ไม่ใช่ช่องของ NRIIS) ถ้าถูกต้องและครบแล้ว
ให้นักวิจัยตั้ง `declaration_confirmed_by_human: true` ใน `project.yaml` ด้วยตัวเอง AI ไม่ตั้งค่านี้แทน

## คำสั่งที่นักวิจัยรันเองได้ทุกเมื่อ

```bash
grantthai route list                                   # รายการเส้นทางผลลัพธ์
grantthai route check --route academic-article work.yaml   # ผลตรวจของเส้นทางเดียว
grantthai validate work.yaml --route nriis-proposal    # ถ้ามีผลตรวจระดับ BLOCK จะจบด้วยรหัส 1
grantthai explain B002                                 # ดูว่ากฎข้อนี้หมายถึงอะไร
grantthai build work.yaml --route nriis-proposal       # สร้าง build/NRIIS_SUBMISSION.md
grantthai build work.yaml --route academic-article     # สร้าง build/ACADEMIC_ARTICLE.md
grantthai fields --required --route academic-article   # ช่องของเส้นทางบทความ เรียงตามลำดับในไฟล์ผลลัพธ์
grantthai migrate project.yaml --dry-run               # ดูว่าถ้าแปลงเป็น work.yaml จะมีการรีวิวไหนหมดอายุ
```

ไฟล์ `project.yaml` แบบเดิมสร้างได้เหมือนเดิมทุกไบต์: `grantthai build project.yaml`
ยังได้ `build/NRIIS_SUBMISSION.md` เหมือนก่อน

## ข้อจำกัด

- มีโปรไฟล์แหล่งทุนมาให้แค่ตัวเดียว คือ `example/FICTIONAL_CALL@0.1` ซึ่งเป็นแหล่งทุนสมมติไว้ทดสอบ
  ผลตรวจเพดานงบและคุณสมบัติที่อิงโปรไฟล์นี้จึงไม่ใช่การตรวจกับแหล่งทุนจริง
- กฎ B003, B004 และ F004 ยังไม่ได้ตรวจในเวอร์ชันนี้ รายงานจะบอกไว้เป็นบรรทัด INFO
  นักวิจัยต้องเทียบเรื่องเหล่านี้กับประกาศทุนเอง
- กฎ F002 (ความใหม่ของระเบียบทุน) ขึ้นกับวันที่ตรวจ ไฟล์เดิมตรวจต่างวันกันอาจได้ผลไม่เหมือนกัน
- โปรไฟล์ย่อยของเส้นทางบทความ (`thai-journal`, `international-journal`) เป็นค่าตั้งต้นของ GrantThai
  ไม่ใช่โปรไฟล์ของวารสารใด ทุกอย่างในนั้นเป็น `NEEDS_VERIFICATION` จนกว่านักวิจัยจะให้คำแนะนำผู้เขียนของวารสารที่ระบุชื่อมา
